## 五、已知风险与注意点

- **限流**：并发已固定 3（`AUDIO_CONCURRENCY`）。若云端仍被拒，备选：换 CI 里降到 1–2；或云端失败就回本地（先确认本地网络）；不要提高并发。
- **重跑安全**：音频按「语音+文本」哈希命名、已存在就跳过，重跑同一批课不会重复生成。
- **失败条目**：单条请求重试 6 次后放弃会打印「放弃：…」，网页对该条退回浏览器语音，重跑可补。检查工作流日志里有没有「失败 N 个」。
- **推送冲突**：工作流用 PAT 提交清单到 `main`；如果你同时在本地往 `main` 推东西，工作流的 `git pull --rebase` 可能冲突，云端跑的时候不要同时推 `main`。
- **Pages 上限**：音频仓库约 1GB 上限，当前 `audio-store/files` 约 9700 个 mp3（含未推送的），推送后注意 `publish_audio.py` 打印的容量。
- **额度**：这次批量遇到过一次会话额度耗尽（所有子代理 429 中断），已恢复。之后不需要再调用子代理，音频和部署都是脚本。
