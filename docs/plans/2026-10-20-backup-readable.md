# 导出的备份文件好读一些

- 状态：已合并到 2026-10-20-batch.md
- 日期：2026-10-20
- 来源：本会话 /dev-ask（一批 3 条里的第 2 条；第 3 条见 2026-10-20-morning-review.md）
- 需求原话：增强导出备份数据可读性
- 用户选择：按推荐（文件本身好读、导入不受影响；不另出单词表，不改字段名）

## 现状

- 导出：site/app.js bkDownload 直接 `JSON.stringify(Backup.make(Sync.dump(), now, location.origin))`，整份一行；d 里是 `{键: [值, 修改时间毫秒]}`，复习卡字段都是缩写（a、s、d…），键的顺序是存进去的先后
- 导入：Backup.parse 只读 app、v、at、origin、d，别的字段不管，所以加说明字段不影响导入，旧备份也照样能导

## 交接单

```text
/dev-task
【目标】导出的备份文件打开就看得懂：每条记录一行、按类别排好、开头有中文说明；导入照常，新旧备份都能导
【要做】
1. site/backup.js（纯函数）加 text(d, at, origin) → 备份文件的文字：
   - 外层字段顺序：app、v、at、origin、说明、d；版本号 v 还是 1（格式没变）
   - 「说明」是一个对象：导出时间（本地时间，写成 2026-10-20 08:30）、来自（网址）、每类条数（按 CATS 的中文名，不算墓碑）、怎么导入（设置页 → 数据 → 导入…；每条是 [值, 修改时间（毫秒）]，值为 0 表示已删除）、字段含义（下面第 2 条）
   - d 按类别分组排：已会 → 设置 → 学习记录和复习卡（learn: → srs: → log:）→ 生词本 → 阅读位置 → 界面状态 → 其他（含 drill:）；每类里值不是 0 的在前、0（已删除）的在后，各自按键名排序
   - 排版：外层每个字段一行；「说明」里每项一行；d 里每条记录一行（键和值写在同一行，值本身压成一行不展开）
2. 字段含义写成 backup.js 里的常量（和 study.js 文件头的说明保持一致，改字段时两处一起改）：
   - learn:<课id>:g<词群号> = 学的日期
   - srs:<词> = 复习卡：a 学习日、s 已过几站、d 下次复习日、l 忘过几次、r 最近一次结果（g 记得 / m 模糊 / f 忘了）、n 复习次数、v 记进熟练度的次数、t 最近复习日、h 最近 6 次第一遍结果、q 答对过的最难题型（0 看词选义 / 1 听音 / 2 例句或看义选词 / 3 拼写）、z 斩、p 学新整群过关的日期、cf 易混词、k 课id、g 词群号、f 火苗、o 词条序号
   - log:<日期> = 当天评分次数 g / m / f、dv 当天复习的到期词数（第 3 条做完后还有 mv 当天做的必做数）
   - vocab:<原形> = 生词本：w 原形、x 点到的写法、m 释义、p 音标、k 出处课、e 出处词条、at 加入日期、o 加入时刻、bk 书中位置、ph 例句词组，另带复习卡字段
   - known:<词> = 1 已会；set:<名字> = 设置；last 上次读的课；lw:<课id>、pos:<课id> 阅读位置；drill:<范围> 巩固做到一半的进度（不导入）
3. site/app.js bkDownload 改用 Backup.text（「导出」和覆盖导入前自动下载的「导入前」备份都走它）
4. tests/backup.test.js 加：text 的结果 parse 回来 d 和原来完全一样（键、值、时间）；d 每条一行；类别顺序对、墓碑在每类最后；说明里的条数等于 summary；旧格式（一整行、没有说明）照样能 parse
5. backup.js 文件开头的说明补一句文件长什么样
【不做】
```
