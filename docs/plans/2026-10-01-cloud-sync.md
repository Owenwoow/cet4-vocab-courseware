## 决定

- 数据按键存 `[值, 修改时间]`，「已会」拆成每词一个键、取消记 0（墓碑），逐键取较新者合并，避免两端整份互相覆盖；时间相同按值排序保证收敛
- 推送节流：普通改动 3 秒、阅读位置 20 秒、两次写入至少隔 10 秒，原因是 GitHub 对创建内容有约每小时 500 次的二级限额
- 首次同步完成前不记录阅读位置，否则本机启动时会用新时间戳写下旧位置，盖掉别的设备更新的位置
- 拉取到别的设备更新的 `last` / `pos` 时自动跳过去并弹提示；在设置页时只刷新不跳
- `history.scrollRestoration = "manual"`，刷新后由页面按记录的词定位
- 关闭页面时不做 keepalive 推送：无法先拉取再合并，直接覆盖会丢别的设备的改动；靠 3 秒防抖和切走页面时的同步兜底
- 计划外补充：部署工作流给 `sync.js` 也加版本号，否则手机会缓存旧脚本
- 验证：浏览器里用模拟的 GitHub 接口测过连接/自动建 Gist/推送/拉取跳转/冲突合并/401 报错/旧数据迁移/刷新回位/设置页返回；真实 token 未验证（AI 不能使用真实凭据）
