# 早上复习重新设计：昨天学的必做、积压按遗忘曲线排、复习量大时自动少学新词

- 状态：已合并到 2026-10-20-batch.md
- 日期：2026-10-20
- 来源：本会话 /dev-ask（一批 3 条里的第 3 条；第 1 条是提问已当场回答，第 2 条见 2026-10-20-backup-readable.md）
- 需求原话：早上复习单词设计优化，我今天背诵单词发现，有无我周末没有复习，导致会有很多单词要复习，但是我希望优先级在正常背诵日的情况下，优先推送昨天学习的单词进行复习，只是一定要完成的事情，不可动摇。从新思考早上复习该怎么设计，也要参考成熟的记忆曲线。
  追加（看到首页的积压提示后）：我发现系统还有这样人性动态的提示，帮我把这种动态分配做好，我点开网页就知道做做，积压太多内容也可以减少新词的学习，打开早上复习开始中会显示复习类型
- 用户选择：第一轮 ①～⑤ 没提异议，按推荐；第二轮选了「三档」「自动减、能手动放开」「并进今天卡片」，复习类型只勾了「结束页按类型统计」（每张卡标类型、顶部显示做到哪段、开始前概览都没勾）

## 调研结论

- 现在的问题出在排序：`SRS.queue` 先排所有拖过期的（d < 今天），再排今天刚到期的。昨天学的词今天第一次到期、不算拖过，排在周末积下的后面；再被每轮 25、每天 120 截断，可能今天轮不到，明天就变成拖过的
- 遗忘曲线（按 FSRS 公式 R = (1 + 19/81 · t/S)^-0.5 粗算，假设到期那天记得 90%）：拖 1 天，间隔 1 天的新词 90% → 82.5%（拖 2 天 76.6%），间隔 7 天的 → 88.8%，间隔 21 天的 → 89.6%。新词拖一天的损失是老词的十几倍
- Anki / FSRS 社区的积压模拟（Jarrett 等，论坛讨论，非官方结论）：「到期日从早到晚」（现在的拖得最久先来）是积压时最差的几种排法之一；「间隔从短到长」「保持率从高到低」在推荐的几种里。来源：forums.ankiweb.net/t/ordering-request-reverse-relative-overdueness/50051、forums.ankiweb.net/t/improving-sort-orders/50081
- 不冲突：「复习规则用固定站点，不用 FSRS」（2026-10-01-vocab-portal.md）——这次只改顺序、上限和学新的量，站点和间隔不动
- 替换旧决定：2026-10-01-vocab-portal.md「每天复习上限：到期的按拖得最久 → 火苗多 → 课本顺序排」、2026-10-12-smart-review.md「当天到期列表：拖得最久的先 → 熟练度低的先」

【目标】早上复习分两层：还没做第一次复习的词（正常就是昨天学的 + 昨天忘的）必做、排最前、不受每天上限限制；其余到期和积压的按「拖一天损失大的先」排，做不完的老词往后。首页「今天」卡片按复习量分三档，告诉你今天怎么做，复习量大时自动少学新词。电脑、手机都做

1. 复习规则（site/srs.js，核心模块；改了同步改 tests/srs.test.js，文件开头规则说明同步改）：
   - 必做：isMust(c, t) = 到期（d ≤ t）且 s = 0（还没做过第一次复习：新学的、生词本新加的、忘了从头再来的、之前拖下没做第一次复习的）
   - 必做的类型（结束页统计用）：mustKind(c, t) → "new" 昨天学的（a = 昨天且 l = 0）/ "lapse" 昨天忘的（a = 昨天且 l ≥ 1）/ "late" 补第一次复习（a 早于昨天）；非必做的：拖过期（d < t）为 "over"，今天到期为 "due"
   - 排序 queue：必做全部在前（必做内部沿用现在的规则：熟练度低的先，复习不到 3 次按课本顺序，3 次以上乱序、形近词相邻）；其余按「计划间隔」分段，间隔短的段在前：
       段 1：s = 1 或 2（间隔约 1～5 天）
       段 2：s = 3，或 s ≥ 4 且熟练度 ≤ 2（约 7～13 天）
       段 3：s ≥ 4 且熟练度 3（14 天）
       段 4：s ≥ 4 且熟练度 4（21 天）
       段 5：s ≥ 4 且熟练度 5（30 天）
     段内沿用现在的规则：拖过期的先、熟练度低的先、复习不到 3 次按课本顺序、3 次以上乱序且形近词相邻
   - 分档：loadTier(L, cap) → "easy"（L ≤ cap / 2）/ "busy"（≤ cap）/ "heavy"（> cap）。L = 今天的总复习量 = 现在还到期的（含必做）+ 今天已做的到期复习数
   - 预计几天清完：forecast(cards, t, cap) 从今天起逐天推：当天到期的进池子，必做全做、其余每天最多做 cap 个，池子清空那天是第几天；不算以后新学的词、不算复习后重排
2. 每天上限（site/study.js）：必做不占上限，每天上限只管其余的。log:<日期> 加字段 mv = 当天做了几个必做（bump 时记），capLeft 改成 cap − (dv − mv)
3. 「今天到期」这一轮（site/study.js scopeInfo("due")）：还有必做时，这一轮只出必做（超过每轮数照常分轮）；必做清完才出其余的（每轮数、剩余上限照旧截断）。巩固页范围列表、结束页「再来一轮（还有 N 个）」的数字跟着改
4. 首页「今天」卡片（site/study.js modToday，原来的橙色积压框 modBacklog 并进来、删掉独立的框）：
   - 顶上一行状态：🟢 今天轻松 / 🟡 复习偏多 / 🔴 积压太多，加一句今天怎么做，例：「🟡 复习偏多（必做 18 + 到期 / 积压 74 = 92 个）：先把复习做完，学新今天最多 1 群」「🔴 积压太多（必做 18 + 到期 / 积压 150 = 168 个）：今天不学新词，按每天 120 个，预计 2 天清完」
   - 「早上复习」这一步分两行：「必做 · N 个」（做完打勾）和「到期 / 积压 · M 个（最早拖了 K 天）」；按钮进同一个 #/drill/due
   - 「我请假了，整体往后顺延…」按钮挪进这张卡，🔴 或连续 3 天没学（原来的条件 gap ≥ 3）时出现，顺延逻辑不变
5. 复习量大时自动少学新词（site/study.js）：
   - 🟢 照常（设置里的「一次学多少」，学完还能接着学）
   - 🟡 今天最多 1 群：学习新词按 1 群取词（设置是 2 群、至少 15 词也按 1 群）；今天已学够 1 群后，「学新」这一步打勾，按钮换成不显眼的「仍要再学 1 群」
   - 🔴 今天不学新词：「学新」这一步写「今天先不学新词」，按钮换成不显眼的「仍要学 1 群」，点了照样能学（按 1 群取词）

【已定的取舍】
- 必做 = 所有到期且还没做过第一次复习的（不只按「昨天」这个日期）：这几种都只记了 1 天左右，拖一天损失最大；平常就是昨天学的 + 昨天忘的，连着几天没复习时最后学的那批也不会掉进积压
- 必做不占每天上限：用户说「一定要完成，不可动摇」；必做每天几十个，撑不爆
- 其余按计划间隔从短到长：同样拖一天，新的掉得多、老的几乎不掉；积压模拟里「到期早的先」最差
- 三档、自动减但能手动放开：🟢 照常，🟡 最多 1 群，🔴 不学；不锁死，只给自己用，进度也要顾
